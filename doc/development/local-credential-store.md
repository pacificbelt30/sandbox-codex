# ローカル暗号化ストアの実装仕様

**日本語** | [English](../en/development/local-credential-store.md)

- 開発版の実装仕様です。公開済みv0.0.2では利用できません。
- 操作方法：[認証情報を暗号化して保存する](../guides/encrypted-credentials.md)。
- 現在の保存方法・対応状況：[認証情報の保存契約](../credential-store.md)。
- 優先する条件：簡単な操作・ローカル完結・追加の常駐サービス不要・WSL／ヘッドレスでの利用。

## 保存方式

| 項目 | 仕様 |
|---|---|
| 既定 | 既存の0700ディレクトリ・0600ファイル保存を維持 |
| 暗号化 | 利用者が明示的に有効化する任意機能 |
| 保存先 | 制御ホストの製品専用プロファイル領域。プロジェクトと共有しない |
| 暗号化する情報 | APIキー・OAuthのaccess／refresh／ID tokenを含む資格情報本体 |
| Proxy管理シークレット | 別の0600ファイル。暗号化ストアの対象外。作業VMへ渡さない |
| 公開メタデータ | 形式の版、プロファイル名、鍵の解除方式、salt、KDFパラメーター、nonce。秘密は含めない |
| 外部サービス | 不要。ネットワークがなくても保存・解錠可能 |
| 実装 | Goバイナリへ組み込み。別のVault・データベース・コンテナを追加しない |

## 鍵と暗号方式

| 項目 | 仕様 |
|---|---|
| データ暗号鍵 | プロファイルごとに暗号学的乱数から256 bitを生成 |
| データの暗号化 | XChaCha20-Poly1305。保存ごとに新しいnonceを生成 |
| 改ざん・取り違えの検出 | 形式の版・プロファイルの識別情報を認証付きデータへ結び付ける |
| パスフレーズ | Argon2idで鍵を導出し、データ暗号鍵を暗号化して保存 |
| salt | プロファイルごとにランダム生成。パスフレーズ変更時にも更新 |
| KDFの負荷 | 既定64 MiB・3回・並列度1。読込時は64〜128 MiB・3〜6回・並列度1〜4に制限 |
| 更新時の負荷 | 解錠済みのデータ鍵を使う。推論・OAuth更新ごとにKDFを実行しない |
| 利用する実装 | Goの既存暗号ライブラリ。暗号アルゴリズム自体は独自実装しない |

- [XChaCha20-Poly1305の実装](https://pkg.go.dev/golang.org/x/crypto/chacha20poly1305)・[Argon2idの実装](https://pkg.go.dev/golang.org/x/crypto/argon2)。
- 鍵を暗号文と同じディレクトリへ平文で保存する自動解錠は提供しない。

## 解錠と日常操作

| 方式・操作 | 仕様 |
|---|---|
| 基本方式 | 認証Proxyを起動するときにパスフレーズを非表示入力 |
| 起動済みProxy | タスクごとの再入力は不要。鍵は既存のProxyプロセスのメモリで保持 |
| Proxy停止・ホスト再起動 | 次回の起動時に再解錠 |
| OSの鍵保管 | 明示した`--keyring`で、既存Secret Serviceの256 bit鍵保護用鍵を利用。ホストの`secret-tool`・利用者D-Busが必要 |
| WSL・SSH・GUIなし | パスフレーズ方式で利用。systemd・D-Bus・TPM・Windows連携を必須にしない |
| 非対話処理 | `--passphrase-fd`でFD 3以上、最大4096バイト。端末・FDがなければ拒否 |
| 鍵の受け渡し | argv・環境変数・設定ファイル・コンテナメタデータ・ログに秘密を載せない |

- ロック済みのOS鍵保管を、パスフレーズや平文保存へ自動で切り替えない。
- 鍵保管backendを追加するためだけの製品専用daemonは作らない。
- Secret Service操作は15秒でタイムアウトし、異常時に別backendへ切り替えない。
- Secret Service利用時は、既存の[利用者セッションのサービス](https://specifications.freedesktop.org/secret-service/latest-single/)を使う。

## 認証Proxyと作業VM

1. ホストでプロファイルを解錠。
2. 認証Proxyが資格情報を読み、上流への接続に使用。
3. 作業VMには短命の仮トークンだけを渡す。
4. OAuth更新結果は、暗号化して永続化してから利用。

- 作業VMへ暗号化ファイル・実資格情報・解除鍵・資格情報socketを渡さない。
- 認証専用Kataは別用途。公式CLIのログイン結果を一時メモリ領域から回収し、成功・取消・失敗後に回収する。
- ホストCLIの認証を自動取り込みしない。

## 保存・ロック・移行

| 操作・条件 | 仕様 |
|---|---|
| OAuth更新 | 既存のStore契約を維持。期待版を比較し、接続世代を維持 |
| 保存 | 暗号化した一時ファイルへ書込み・fsync・atomic rename・ディレクトリfsync |
| 保存失敗・版競合 | 成功として扱わない。Proxy側の新規要求・既存streamを失効 |
| 明示ロック | 対象プロファイルの実行を停止・失効させ、資格情報を保持するProxyも停止 |
| ロック後 | 保存済み暗号文は保持。作業成果も保持 |
| 平文からの移行 | 明示操作。暗号化保存・再読込の検証後に切り替える |
| 既存プロファイル | 自動で変換・上書きしない |
| パスフレーズ変更 | データ鍵を新しい導出鍵で再保護。失敗時に旧方式を破壊しない |
| 鍵紛失 | 復号不可として扱う。再認証で新しい接続を作る |
| backup復旧・複製 | 再認証と新しい接続世代で再開。旧ワーカーを自動再認可しない |

## 保護の範囲

- 主な保護対象：停止中の保存ファイル・ディスクやbackupからの資格情報の読取り。
- 保存暗号化だけで保護できない対象：制御ホストのroot、同一UIDによるプロセスの読取り、稼働中のメモリ・swap・VM snapshot。
- Goのメモリ管理上、秘密の全コピーを確実にゼロ化できるとは保証しない。不要なコピーを減らし、利用プロセスの終了で保持期間を限定する。
- 外側のVM snapshotで鍵・暗号文・世代情報を同時に巻き戻された場合、ローカルだけで完全検知できるとは保証しない。
- WSLはLinux側の保存先を基本とする。DrvFS・共有filesystemは権限・永続化の保証を確認したものだけ対応対象にする。

## 検証項目と残る確認

- 誤パスフレーズ、暗号文改ざん、取り違え、巨大なKDF指定を拒否する。
- 保存失敗・同時更新・取消・Proxy再起動・鍵backendの利用不能で、平文保存やホスト認証へ切り替わらない。
- 作業VMのファイル・環境変数・ログ、ホスト側の通常ログ・コンテナメタデータへ実秘密が残らない。
- 既存のStore適合性試験と、実Kataの受入試験を通す。
- 解錠時間とメモリ、通常推論・OAuth更新時の追加負荷を測定する。

- 既存のStore適合性試験は暗号化版にも適用。架空の資格情報で、移行途中の復旧・パスフレーズ変更・キーリング障害を試験します。
- **平文`.json`と暗号化`.vault`が共存する状態**を移行未完了として拒否します。
- 保存・移行中の失敗で暗号文が配置済みか不明なときは鍵保管を削除せず、復旧可能性を残します。
- 外部Storeの公開`Store`契約は変更しません。暗号化は追加の`EncryptedStore`実装です。
- [測定値・実Kata結果・未確認事項](../testing.md)を参照。
